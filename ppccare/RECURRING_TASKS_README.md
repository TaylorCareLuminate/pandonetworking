# Recurring Task Scheduling System

## Overview
The recurring task scheduling system allows you to automate the creation of task groups on a recurring basis (daily, weekly, monthly, or quarterly). Tasks are automatically created by a Railway cron job that runs every hour.

## System Components

### 1. Frontend Interface (`repeat_scheduled_tasks.html`)
**Location**: `HealthLuminateSite/ppccare/repeat_scheduled_tasks.html`

A user-friendly interface for creating and managing recurring task schedules with two main sections:

#### Create Schedule Tab
- **Schedule Information**: Name, status (active/paused), and optional description
- **Task Group Selection**: Choose from existing Customer Support task groups
- **Frequency Configuration**:
  - **Daily**: Runs every day at specified time
  - **Weekly**: Select specific days of the week
  - **Monthly**: Choose day of month (1st, 15th, or last day)
  - **Quarterly**: Runs on the 1st of Jan, Apr, Jul, Oct
- **Time of Day**: Specify UTC time when tasks should be created
- **Start Date**: When the schedule should begin
- **Organization Selection**:
  - **All Organizations** (recommended): Automatically creates tasks for all active organizations
  - **Specific Organizations**: Select individual organizations

#### Manage Schedules Tab
- View all existing recurring schedules
- See schedule details: frequency, next run, organization count
- Pause/activate schedules
- Delete schedules
- Track last run and tasks created

### 2. Backend Processor (Railway)
**Location**: `RailwayCLemail/server.js` (lines 399-755)

#### Function: `processRecurringTasks()`
Runs every hour via cron job to check and execute scheduled tasks.

**Process Flow**:
1. **Fetch Data**: Reads from Firebase Realtime Database (HealthcareITDatabase):
   - `ppccare/scheduled_tasks` - Schedule definitions
   - `ppccare/task_groups` - Task group templates
   - `ppccare/companies` - Organization data
   - `ppccare/questions_db` - Question definitions
   - `ppc_kare_25` - KARE role assignment data
   - `ppccare/roles` - Role to column mappings

2. **Check Schedule Eligibility**: For each schedule, determines if it should run by checking:
   - Status is 'active'
   - Current UTC hour matches scheduled time
   - Hasn't already run in this hour today
   - Frequency conditions are met (day of week, day of month, etc.)

3. **Create Tasks**: For schedules that should run:
   - Resolves which organizations to target (all or specific)
   - Creates tasks exactly like the frontend `assign_task_groups_customers.html`:
     - Applies UTC-based date calculations
     - Resolves role names to actual people using KARE data
     - Includes checklist items, questions, and resource URLs
     - Sets proper task metadata and tracking fields
   - Saves tasks to `ppccare/tasks`

4. **Update Schedule**: Records `lastRun`, `lastRunDate`, and `lastRunTasksCreated`

#### Cron Schedule
```javascript
cron.schedule('0 * * * *', async () => {
  // Runs at the top of every hour (UTC)
  const result = await processRecurringTasks();
  console.log(`✅ Recurring tasks processed: ${result.tasksCreated} tasks created`);
});
```

## Database Structure

### Schedule Record (`ppccare/scheduled_tasks`)
```javascript
{
  scheduleId: "schedule_1699123456789_abc123",
  name: "Monthly Client Check-in",
  status: "active", // or "paused"
  description: "Monthly check-in tasks for all clients",
  taskGroupId: "task_group_xyz",
  frequency: "monthly", // "daily", "weekly", "monthly", "quarterly"
  frequencyOptions: {
    daysOfWeek: [1, 3, 5], // For weekly: 0=Sun, 6=Sat
    dayOfMonth: "1" // For monthly: "1", "15", "last"
  },
  timeOfDay: "09:00", // UTC time
  startDate: "2025-11-05",
  allOrganizations: true, // or false
  organizationIds: [], // If not allOrganizations
  createdDate: "2025-11-05T10:00:00.000Z",
  createdBy: "user@example.com",
  lastModified: "2025-11-05T10:00:00.000Z",
  lastRun: "2025-11-06T09:00:00.000Z",
  lastRunDate: "2025-11-06",
  lastRunTasksCreated: 45
}
```

### Created Task Record (`ppccare/tasks`)
Tasks created by recurring schedules have these additional fields:
```javascript
{
  // Standard task fields...
  source_schedule_id: "schedule_1699123456789_abc123",
  source_schedule_name: "Monthly Client Check-in",
  task_creation_leader: "recurring-scheduler",
  task_creation_leader_id: "system",
  task_desc: "Task from [Group Name] (Auto-generated by recurring schedule: [Schedule Name])"
  // ...rest of task fields
}
```

## Key Features

### 1. UTC-Based Date Handling
All date calculations use UTC to prevent timezone-related issues:
```javascript
const [year, month, day] = dateString.split('-').map(num => parseInt(num, 10));
const date = new Date(Date.UTC(year, month - 1, day, 12, 0, 0));
date.setUTCDate(date.getUTCDate() + daysToAdd);
```

### 2. Role Resolution
Tasks automatically resolve role names (e.g., "Account Manager") to actual people using KARE data:
- Looks up organization's KARE record by Bullhorn ID
- Finds the person assigned to that role column
- Falls back to role name if person not found

### 3. All Organizations Mode
When enabled:
- Automatically includes new organizations added after schedule creation
- Filters to only active organizations with Bullhorn IDs
- No need to update schedule when adding new clients

### 4. Resource URLs
Resource URLs from task group definitions are:
- Included in task descriptions with 🔗 emoji
- Stored in `task_resource_url` field
- Displayed as clickable links in My Tasks page

### 5. Questions and Checklists
Full support for:
- Checklist items (displayed in task description)
- Questions with proper data structures for responses
- All question types: status, yes/no, free response, rating, etc.

## Usage Examples

### Example 1: Monthly Client Check-in
```
Name: Monthly Client Check-in
Frequency: Monthly (1st of month)
Time: 09:00 UTC
Task Group: Monthly Status Review
Organizations: All Organizations
Status: Active
```
**Result**: On the 1st of every month at 9 AM UTC, tasks are created for all active clients.

### Example 2: Weekly Team Huddle
```
Name: Weekly Friday Huddle Prep
Frequency: Weekly (Friday)
Time: 14:00 UTC
Task Group: Huddle Preparation Tasks
Organizations: [Specific list]
Status: Active
```
**Result**: Every Friday at 2 PM UTC, preparation tasks are created for selected clients.

### Example 3: Quarterly Business Review
```
Name: Quarterly Business Review
Frequency: Quarterly
Time: 08:00 UTC
Task Group: QBR Preparation
Organizations: All Organizations
Status: Active
```
**Result**: On January 1st, April 1st, July 1st, and October 1st at 8 AM UTC, QBR tasks are created for all active clients.

### Common Issues

**Issue**: Tasks not being created
- **Check**: Schedule status is "active"
- **Check**: Current UTC time matches schedule time
- **Check**: Schedule hasn't already run this hour
- **Check**: Railway logs for errors

**Issue**: Wrong organizations getting tasks
- **Check**: `allOrganizations` setting
- **Check**: `organizationIds` array if using specific orgs
- **Check**: Organization status is "Active" with valid Bullhorn ID

**Issue**: Tasks missing questions or checklists
- **Check**: Task group has properly saved questions/checklist
- **Check**: Questions exist in `ppccare/questions_db`
- **Check**: Railway logs for question resolution errors

**Issue**: Role names not resolving to people
- **Check**: KARE data has Bullhorn ID matching customer
- **Check**: Role mapping exists in `ppccare/roles`
- **Check**: KARE column has assigned person (not "NA" or empty)

## Technical Notes

### Firebase Connection
The Railway server uses:
- Firebase Admin SDK for server-side operations
- Firebase Realtime Database (not Firestore)
- Database URL: `https://clemail-default-rtdb.firebaseio.com`
- Connects to HealthcareITDatabase tables under `ppccare/` namespace

### Performance
- Cron job runs hourly (can be adjusted in server.js)
- Processes all schedules in parallel where possible
- Task creation is batched per organization
- Average execution time: 10-30 seconds for 50+ organizations

### Scaling Considerations
- No hard limits on number of schedules
- Tested with 50+ organizations, 10+ task groups
- Consider reducing cron frequency if creating 1000+ tasks per run
- Firebase Realtime Database can handle the load
