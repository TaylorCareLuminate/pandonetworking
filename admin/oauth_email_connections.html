OAuth Email Connections

Connect Google and Microsoft accounts securely — no App Passwords required

Email Controls Admin Panel Dashboard
How this works: Users click "Connect Account" below, approve permissions at Google or Microsoft (one time), and your Railway backend securely stores their refresh token. No passwords are ever stored — tokens are encrypted and rotate automatically.
  • Gmail uses Gmail API + Google Pub/Sub for real-time reply detection (no IMAP polling)
  • Outlook uses Microsoft Graph + Change Notifications for real-time reply detection
  • Access tokens refresh silently every hour — users never need to re-authorize
  • Use the Monitoring toggle on each connected account below to stop scanning an inbox for replies — the account stays connected and can still send email, it just won't be watched or forwarded to taylordavis@healthluminate.com

Connect an Account

Start the OAuth flow for a Google Workspace or Microsoft 365 account

Google / Gmail

Connect a Gmail or Google Workspace account to send prospecting emails and detect replies via Gmail API.

Permissions requested:
  • Read and send emails (gmail.modify)
  • View your email address
  • Read & write calendar events (calendar.events)

Microsoft / Outlook

Connect an Outlook or Microsoft 365 account to send emails and detect replies via Microsoft Graph API.

Permissions requested:
  • Read and send emails (Mail.ReadWrite, Mail.Send)
  • View your profile (User.Read)
  • Read & create calendar events for scheduling (Calendars.ReadWrite)

Contacts can connect themselves at /connect/microsoft_oauth.html (Microsoft only — email + calendar).

Why this happens: Some organizations (like OutcomeMD) restrict their users from consenting to third-party apps. Their Azure AD admin must approve the app for their tenant — just once — before any user in that org can sign in.

The permissions shown in the app registration are on your side. Each client organization needs to separately grant consent in their own Azure AD tenant.

Send the generated URL to the client's IT admin. They sign in with a Global Admin account and click "Accept" — then all users in that org can connect.
