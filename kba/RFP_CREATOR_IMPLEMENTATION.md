## Overview
The RFP Creator is a new tool in the KBA section that uses AI to help generate responses to RFP (Request for Proposal) questions based on past responses. It leverages OpenAI through the Railway backend to learn from historical RFP responses and generate contextually appropriate answers.

## Components Created

### 1. Frontend: `rfp_creator.html`
**Location:** `c:\repos\HealthLuminateSiteFromLocal\kba\rfp_creator.html`

**Features:**
- **Two-Section Design:**
  - **Top Section:** Upload and manage past RFP responses
  - **Bottom Section:** Generate responses to new RFP questions

- **Past RFP Responses Section:**
  - Upload question/response pairs from historical RFPs
  - Automatic AI summarization in the background
  - View all past responses with summaries
  - Delete unwanted responses
  - Data stored in Firebase Realtime Database at `kba/rfp_past_responses`

- **Generate New Responses Section:**
  - Paste multiple questions (one per line)
  - AI generates responses based on past RFP knowledge
  - Processes questions one at a time
  - Shows generated responses immediately
  - AI will refuse to answer if insufficient context exists

**Firebase Integration:**
- Uses dual Firebase setup:
  - **Auth:** HealthLuminate Firebase (authentication)
  - **Data:** HealthcareITDatabase Realtime Database (data storage)
- Database path: `kba/rfp_past_responses`
- Structure:
  ```
  {
    responseId: {
      question: string,
      response: string,
      summary: string (generated by AI),
      uploadedAt: timestamp,
      uploadedBy: email,
      summarizedAt: timestamp
    }
  }
  ```

### 2. Backend: Railway Endpoints
**Location:** `c:\repos\RailwayCLemail\server.js` (before SERVER STARTUP section)

**Endpoints Added:**

#### POST `/api/rfp/summarize`
Summarizes past RFP questions and responses for better semantic search.

**Request Body:**
```json
{
  "responseId": "firebase-key",
  "question": "Original RFP question",
  "response": "Your response to the question"
}
```

**Response:**
```json
{
  "success": true,
  "responseId": "firebase-key",
  "summary": "Brief summary of the question"
}
```

**Behavior:**
- Uses GPT-4o-mini for cost efficiency
- Creates concise single-sentence summaries
- Saves summary back to Firebase Realtime Database
- Runs in background (non-blocking)

#### POST `/api/rfp/generate`
Generates responses to new RFP questions based on past responses.

**Request Body:**
```json
{
  "question": "New RFP question to answer",
  "pastResponses": [
    {
      "id": "response-id",
      "question": "past question",
      "response": "past response",
      "summary": "summary"
    }
  ]
}
```

**Response:**
```json
{
  "success": true,
  "question": "The question asked",
  "response": "AI-generated response"
}
```

**Behavior:**
- Uses GPT-4o for high-quality responses
- Takes up to 10 most recent past responses as context
- Instructs AI to refuse if insufficient knowledge exists
- Matches company tone and style from past responses
- Temperature: 0.7 (balanced creativity)
- Max tokens: 1000

**AI Safety Instructions:**
- Must not make up information
- Must say "I have not been trained to answer this question yet" if insufficient context
- Must be consistent with past responses
- Must match company tone and style

## User Workflow

### Step 1: Upload Past RFP Responses
1. Navigate to RFP Creator from KBA navigation
2. Enter a question from a past RFP
3. Enter the response that was provided
4. Click "Upload Response"
5. AI summarizes the Q&A in the background
6. Response appears in the list below

### Step 2: Generate New RFP Responses
1. Paste new RFP questions (one per line) in the bottom section
2. Click "Generate Responses"
3. AI processes each question one at a time
4. Generated responses appear below
5. If AI lacks context, it will explicitly state it hasn't been trained

## Technical Details

### OpenAI Integration
- **Summarization:** GPT-4o-mini (cost-efficient for simple tasks)
- **Generation:** GPT-4o (high quality for important responses)
- API Key: Uses existing `OPENAI_API_KEY` from Railway environment

### Error Handling
- Frontend shows clear error messages
- Backend logs all errors with context
- Graceful degradation if AI is unavailable
- Validation for required fields

### Security
- Requires HealthLuminate authentication
- Firebase security rules apply to data access
- Railway backend handles all OpenAI calls (API key not exposed)
- CORS configured for healthluminate.com

## Design Choices

1. **Background Summarization:** Summaries are generated asynchronously to keep upload UX fast
2. **Sequential Generation:** Questions processed one at a time to show progress and avoid rate limits
3. **Safety First:** AI explicitly instructed to refuse rather than hallucinate
4. **Dual Firebase:** Maintains existing auth pattern while using shared data storage
5. **Real-time Updates:** Firebase listeners automatically update the UI when summaries complete
