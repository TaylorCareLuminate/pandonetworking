OutcomeMD Portal Access Test

Test Instructions

This page tests the dual access control system for the OutcomeMD client portal.

  • ✅ Override Access: Users with @outcomemd.com email addresses (always allowed)
  • ✅ Folder Permission Access: Other domains added to the OutcomeMD folder permissions in Firestore
  • ❌ Denied: All other email domains not in either category
  • ⏱️ Redirect: Access denied users will see a message and be redirected to login after 10 seconds

Implementation Details

Dual Access System:

  • isOutcomeMDClient() - Implements dual access logic:
    1. First checks if domain === 'outcomemd.com' (override)
    2. If not, falls back to folder permission check
  • handleAccessDenied() - Shows message and handles 10-second redirect
  • findClientCustomer() - Uses isOutcomeMDClient() for consistent access control

Access Priority (Fail-Safe Design):

Prioritizes Accessibility:
  • Priority 1: @outcomemd.com emails - ALWAYS allowed (hardcoded override)
  • Priority 2: Folder permissions - flexible partner access via Firestore
  • Default: Deny with clear messaging and auto-redirect
  • Multiple fail-safes ensure legitimate users can access
  • Clear user feedback about access requirements

How to Add Partner Access

To grant access to partners or other domains (beyond @outcomemd.com):

  1. Go to Firebase Console → Firestore Database
  2. Navigate to folderPermissions collection
  3. Find or create document with ID: outcomemd
  4. Add the partner's domain to the allowedDomains array
  5. Save the document
Example Firestore Document: 
{
  "folderName": "outcomemd",
  "allowedDomains": [
    "healthluminate.com",
    "partner-company.com",
    "another-partner.org"
  ],
  "createdAt": "2024-01-01",
  "updatedBy": "admin@outcomemd.com"
}

// Dual access system (line ~1202)
async function isOutcomeMDClient(user) {
  const domain = getDomainFromEmail(user.email);
  
  // OVERRIDE: Always allow outcomemd.com email addresses
  if (domain === 'outcomemd.com') {
    console.log('✅ OVERRIDE: OutcomeMD domain - automatic access');
    return true;
  }
  
  // FALLBACK: Check folder permissions for other domains
  try {
    const hasAccess = await window.checkFolderAccess('outcomemd', user.email, {
      allowOnError: false,
      allowOnMissing: false
    });
    return hasAccess;
  } catch (error) {
    console.error('❌ Error checking folder access:', error);
    return false;
  }
}

// New access denial handler (line ~1160)
function handleAccessDenied(userEmail = null) {
  // Hide loading
  document.getElementById('loading').style.display = 'none';
  
  // Show access denied
  document.getElementById('access-denied').style.display = 'block';
  
  // Update user info
  if (userEmail) {
    document.getElementById('denied-user-email').textContent = userEmail;
    const domain = getDomainFromEmail(userEmail);
    document.getElementById('denied-user-domain').textContent = domain;
  }
  
  // Start 10-second countdown
  let countdown = 10;
  const countdownInterval = setInterval(() => {
    countdown--;
    document.getElementById('redirect-countdown').textContent = countdown;
    
    if (countdown <= 0) {
      clearInterval(countdownInterval);
      window.location.href = '../login.html';
    }
  }, 1000);
}
