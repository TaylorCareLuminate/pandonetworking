## How the Cost/Revenue Tracking Works

### Data Sources

1. **`connect_queue` collection**
   - All generated messages (LinkedIn posts, internet search, profile messages, etc.)
   - Filters by `generated_at`, `bdr_auth_email`
   - Maps `generated_via` or `uploadedVia` fields to activity types

2. **`heyreach_activity` collection**
   - All HeyReach webhook events
   - Filters by `timestamp`, `bdrEmail`
   - Maps `eventType` to activity types
   - **Important**: Only counts activities from OUR BDRs (matches `bdrEmail` against our BDR list)

3. **Future: `activity_tracking` collection** ✅ **NOW IMPLEMENTED**
   - Follow-up messages (individual and bulk)
   - Meeting scheduled events
   - See `TRACKING_IMPLEMENTATION.md` for complete details

### Revenue Calculation Process

```javascript
1. Load messages from connect_queue
2. Load activities from heyreach_activity
3. Load activity tracking data (follow-ups, meetings) ✅ NEW
4. Categorize each activity by type
5. Look up cost from settings (or use defaults)
6. Group by BDR and Company
7. Calculate totals and breakdowns
8. Display in UI
```

## Tracking fields needed in Backend

When backend generates messages from LinkedIn posts or internet search, ensure these fields are set:

```javascript
// For LinkedIn Post Messages
{
  generated_via: 'linkedin_post_reply',  // ← Key field for tracking
  source: 'LinkedIn Post',               // ← Alternative/legacy field
  post_text: string,                     // The LinkedIn post text
  post_url: string,                      // URL to the LinkedIn post
  bdr_auth_email: string,                // BDR identification
  generated_at: timestamp,               // For date filtering
  prospect_company: string,              // For company reporting
  prospect_name: string                  // For contact counting

// For Internet Search Messages
{
  generated_via: 'internet_search',      // ← Key field for tracking
```

## Technical Notes

### Firestore Security Rules
Ensure `settings/cost_revenue_tracking` document:
- Can be read by admins
- Can be written by admins
- Structure: `{ costs: {...}, updatedAt: timestamp, updatedBy: email }`

### Performance Considerations
- Connect_queue queries limited to 1000 documents (adjust if needed)
- HeyReach_activity queries limited by date range
- Consider adding indexes for:
  - `connect_queue`: `bdr_auth_email + generated_at`
  - `heyreach_activity`: `bdrEmail + timestamp`

### Data Validation
The tracking logic handles missing data gracefully:
- Unknown source types are skipped (not counted)
- Missing BDR emails show as "Unknown"
- Missing companies show as "Unknown"
- Zero-cost activities are included in counts but don't affect revenue
