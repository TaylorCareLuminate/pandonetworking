Full Pipeline
One page that runs the entire flow: organization URL research → Apify employee contact scan (with cost tracking) → target-rule filtering → organization news (fetched once per org) → Full AI Generate → Opus Review → Final AI Reviews. Finished messages land in Fast Connect Review exactly like today. See Full Pipeline Dashboard for a breakdown of every past run (why contacts were dropped, cost, conversion rate).

2 BDRs & Messages to Generate

Organizations from the group are scanned one at a time; each organization's contacts are assigned to whichever checked BDR's turn it is, alternating between BDRs round-robin until every BDR's count is met (a BDR that reaches its target early drops out and the rest keep alternating).

4 Employee Contact Scan Rules

Identical criteria to Employee Contact Scanning on Prospect Organizations Admin — one scan job per organization, processed by the same backend, with Apify costs tracked in the same ledger.

Reads the Step 1 rules and suggests job functions, seniority levels, and — most useful — Job Title Keywords. Review before running.

Before scanning, an AI agent looks at each organization (name, industry, state, description, LinkedIn URL — whatever is on file) and assigns it to one of the types below. Each type gets its own complete set of Employee Contact Scan Rules (Job Functions, Seniority, Job Title Keywords, etc. — even its own fallback scan), so e.g. hospitals and technology vendors in the same hypothesis group can be scanned completely differently. 6 Cost Shut-Down Rates

The pipeline stops automatically when contact-search spend gets out of line with messages produced. Of the target cost per message, roughly $0.03 goes to AI (build + reviews) and $0.02 to post scrapes, so the rest is the Apify contact-search budget. When the average Apify cost per generated message exceeds that budget, the run shuts down — that usually means the Step 4 scan rules are finding too few usable contacts and need adjusting.

Default $0.20 per generated message.

Ask Opus to Review This Run

Sends the complete run log exactly as printed above, this run's search criteria/scan rules/models/cost settings, and the totals this run computed to Claude Opus, and asks it for plain-English feedback grounded in this specific run — what's working, what's not, and what to fix, ranked by impact. You can run this any time after the run starts producing log lines; it doesn't have to wait for the run to finish.

Data Repair: Misassigned / Orphaned Contacts

Scans every message this pipeline has ever generated (across all hypothesis groups and all BDRs — not just the group selected above) and cross-checks it against the full_pipeline_runs record it was created under. Catches three known failure modes: (1) a message's hypothesis group stamp was silently overwritten with the wrong group later (usually by Fast Connect Review's auto-detect-by-URL logic matching a different group the same contact/org happens to also be tagged under), (2) a message never got a hypothesis group stamp at all even though its run had one, and (3) a hypothesis group's tagged-contact URL list never got backfilled during a run, which starves Outcomes by Hypothesis Group and the Batch ↔ Hypothesis Group Correlation tool of anything to match against. Also flags runs stuck at "running" with no activity, which otherwise never show up as needing attention anywhere.
