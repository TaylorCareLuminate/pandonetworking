WHAT WAS ADDED
--------------
A new function `bebity_company_search()` was added to the bebity_profile_search.R
file. This function searches for LinkedIn company/organization pages with
intelligent caching to avoid redundant searches and save API costs.


KEY FEATURES
------------
✓ Automatic caching - searches are saved and reused
✓ GPT-powered name matching - finds cached results for similar organization names
✓ Fully backward compatible - doesn't affect existing bebity_profile_search()
✓ Cost savings - only pay for new searches, not repeats
✓ Easy integration - uses existing RProfile functions (saver, loadr, gpt.batch)

HOW THE CACHING WORKS
----------------------
1. User searches for "Sarasota Memorial Hospital"

2. Function checks cache database:
   - Cache location: C:/Users/TaylorDavis/OneDrive - CareLuminate/R Input Files/In Process AI/Bebity LinkedIn Company Profiles/
   - File: company_search_cache.rdata

3. If GPT matching enabled (default):
   - Uses gpt.batch() to compare search term with cached searches
   - Matches similar names (e.g., "Sarasota Memorial" = "Sarasota Memorial Hospital")

4. If found in cache:
   - Returns cached results immediately (FREE!)
   - Sets is_cached = TRUE

5. If NOT found in cache:
   - Performs Apify search (costs API credits)
   - Saves results to cache using saver()
   - Sets is_cached = FALSE


CACHE DATABASE STRUCTURE
-------------------------
The cache stores a data frame with these columns:

- search_query: Original search term used
- organization_name: Organization name found on LinkedIn
- linkedin_url: LinkedIn company page URL
- search_date: Date when search was performed

Example:
  search_query              organization_name        linkedin_url
  "Sarasota Memorial Hosp"  "Sarasota Memorial..."   "linkedin.com/company/..."
  "Mayo Clinic"             "Mayo Clinic"            "linkedin.com/company/..."


INTEGRATION WITH RPROFILE FUNCTIONS
------------------------------------
The function uses three RProfile functions:

1. saver(object, name)
   - Used to save cache database
   - Saves to: R Input Files/In Process AI/Bebity LinkedIn Company Profiles/

2. loadr(name)
   - Used to load cache database
   - Handles errors gracefully if cache doesn't exist

3. gpt.batch(df, prompt)
   - Used for intelligent name matching
   - Compares search terms to find similar organization names
   - Optional - function works without it (just less smart matching)

  message("New search (API cost incurred)")

COST SAVINGS EXAMPLE
--------------------
Scenario: You search 100 hospitals multiple times

Without caching:
  Day 1: Search 100 hospitals = $0.80
  Day 2: Search same 100 hospitals = $0.80
  Day 3: Search same 100 hospitals = $0.80
  Total: $2.40

With caching:
  Day 1: Search 100 hospitals = $0.80
  Day 2: Search same 100 hospitals = $0.00 (from cache)
  Day 3: Search same 100 hospitals = $0.00 (from cache)
  Total: $0.80

Savings: $1.60 (67% reduction)
