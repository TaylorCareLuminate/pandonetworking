WHAT WAS BUILT
══════════════

A new V2 version of bebity_company_search() with intelligent 3-round search strategy:

✓ ROUND 1: Cache check + initial Apify search
✓ ROUND 2: GPT verification + Gemini alternative names + search
✓ ROUND 3: Final Gemini attempt with targeted search

All results are automatically saved to cache for future use!


HOW THE MULTI-ROUND SYSTEM WORKS
═════════════════════════════════

ROUND 1: Cache Check + Initial Search
──────────────────────────────────────
FOR EACH ORGANIZATION:
  1. Check if organization's LinkedIn URL is in cache
  2. If found → return cached result (FREE!)
  3. If NOT found → search Apify with original name
  4. Save any results to cache

Example:
  Search: "Sarasota Memorial Hospital"
  → Not in cache
  → Search Apify
  → Found 3 results
  → Save to cache


ROUND 2: GPT Verification + Gemini Alternatives
────────────────────────────────────────────────
STEP 1 - GPT Verification (for ALL organizations):
  • Uses gpt.batch to compare search query with found organization names
  • Verifies if "Sarasota Memorial Hospital" matches "Sarasota Memorial Health Care"
  • Updates match_confidence to "gpt_verified" or "gpt_mismatch"

STEP 2 - Gemini Alternative Names (for UNFOUND organizations):
  • Uses gemini.batch to generate 2-3 alternative names
  • Example: "JHH" → generates "Johns Hopkins Hospital | Johns Hopkins Health System | JHU Medicine"
  • Searches each alternative name via Apify
  • Saves results to cache with original query name

Example:
  Original search: "JHH"
  Round 1: No results
  Round 2:
    → Gemini generates: "Johns Hopkins Hospital | Johns Hopkins Health System"
    → Search "Johns Hopkins Hospital" → Found 5 results!
    → Save to cache as search_query="JHH"


ROUND 3: Final Gemini Attempt
──────────────────────────────
FOR EACH STILL-UNFOUND ORGANIZATION:
  • Gemini generates ONE best search term
  • Prompt asks for "EXACT name to find their official LinkedIn page"
  • Considers parent organizations, health systems, etc.
  • Final search attempt via Apify
  • Save results to cache

Example:
  Original search: "Memorial Hospital of South Texas"
  Rounds 1-2: No results
  Round 3:
    → Gemini suggests: "Mission Health System"
    → Search "Mission Health System" → Found 2 results!
    → Save to cache as search_query="Memorial Hospital of South Texas"

CACHE DATABASE STRUCTURE
═════════════════════════

The cache now stores additional information:

┌───────────────┬──────────────────┬────────────────────┬──────────┬──────────┬────────────────┐
│ search_query  │ organization_name│ linkedin_url       │ search   │ search   │ match          │
│               │                  │                    │ _date    │ _round   │ _confidence    │
├───────────────┼──────────────────┼────────────────────┼──────────┼──────────┼────────────────┤
│ JHH           │ Johns Hopkins... │ linkedin.com/...   │ 2024-... │ 2        │ gemini_alter...│
│ Mayo Clinic   │ Mayo Clinic      │ linkedin.com/...   │ 2024-... │ 1        │ gpt_verified   │
│ Mass General  │ Massachusetts... │ linkedin.com/...   │ 2024-... │ 2        │ gemini_alter...│
└───────────────┴──────────────────┴────────────────────┴──────────┴──────────┴────────────────┘

New columns:
• search_round: Which round found this result (1, 2, or 3)
• match_confidence: How the match was verified
  - "round1_direct" = Found in Round 1 direct search
  - "gemini_alternative" = Found via Gemini alternative name (Round 2)
  - "gemini_final" = Found via final Gemini attempt (Round 3)
  - "gpt_verified" = GPT confirmed the match
  - "gpt_mismatch" = GPT flagged potential mismatch
  - "cached" = Result from cache


INTEGRATION WITH YOUR FUNCTIONS
════════════════════════════════

The V2 function uses FOUR functions from your RProfile:

1. saver(object, name)
   • Saves cache database
   • Used after each successful search

2. loadr(name)
   • Loads cache database
   • Used at startup

3. gpt.batch(df, prompt)
   • Verifies organization matches in Round 2
   • Compares search queries with found names

4. gemini.batch(df, prompt)
   • Generates alternative search names in Round 2
   • Generates final search term in Round 3
   • MORE CREATIVE than GPT for alternative names

WHEN TO USE V1 vs V2
════════════════════

USE V1 IF:
• Searching well-known organizations with standard names
• Speed is critical
• Budget is very tight
• Simple cache check → search → done is sufficient

USE V2 IF:
• Searching organizations with abbreviations or nicknames
• Names vary significantly (Mass General vs Massachusetts General Hospital)
• Maximum accuracy is important
• Willing to invest more initially for better results
• Want intelligent alternative name generation
• Need match verification


RECOMMENDED WORKFLOW
════════════════════

1. Start with V2 for initial data collection
   • Finds more organizations
   • Better match verification
   • Builds comprehensive cache

2. Use V1 for routine updates
   • Faster for known organizations
   • Cache already populated from V2

3. Use V2 again when adding new organizations
   • Handles difficult names better
   • Smarter alternative generation
