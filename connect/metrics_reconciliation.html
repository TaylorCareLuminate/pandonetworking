Reserve Queue Trace — Where Did the Missing Messages Go?

fast_connect_review.html's "Send Checked to Reserve" (and the automatic low-connections auto-reserve path inside "Submit Batch") is a two-step process: step 1 marks the message approved directly in connect_queue; step 2 calls /api/reserve-queue/add-batch to actually copy it into connect_reserve_queue and delete the original. If step 2 fails or times out partway through a large batch, step 1 already happened — so the message silently disappears from every Queue 1 / Queue 2 count on every page — but it never arrives in the Reserve Queue either. This panel finds every message ever routed this way for the selected BDR and tells you exactly which bucket it landed in.

Promoted OUT of Reserve — Stuck (Not Yet Pushed to HeyReach)

The opposite direction: reserve messages that were promoted into connect_queue (either by the 6 AM auto top-up or a manual promote) should get picked up and pushed to HeyReach on the very next 30-minute push cycle. This count should always be 0. If it's not, the most common cause is the BDR's customer having HeyReach disabled or missing an API key — the push cron skips the entire customer silently in that case, so these messages will never clear on their own.
